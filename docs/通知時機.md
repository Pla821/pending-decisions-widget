# 什麼時候會跳通知／對話框

這份是照程式實際行為整理的（`src/bin/decision-log.mjs`、`decision-scan.mjs`、`lib.mjs`、`widget.ps1`、`toast.ps1`），不是設計稿。
寫了「未驗證」的地方，是程式碼看不出來、或沒有實際在 Claude 桌面版上測過的。

## 先搞懂三個「偵測者」

| 偵測者 | 什麼時候醒 | 做什麼 |
|---|---|---|
| **hook**（`decision-log.mjs`） | Claude Code 觸發事件的**當下**（要先把 hook 註冊進 `settings.json`，而且對話是在註冊**之後**才開的） | 記進清單、**馬上跳 Windows 通知**、（選填）推手機 |
| **掃描**（`decision-scan.mjs`） | 小工具每 **6 秒**叫一次；讀所有對話的紀錄檔尾端 | 找「問了、還沒回」的事，寫進清單。**不跳 Windows 通知**，不需要 hook |
| **小工具**（`widget.ps1`） | 每 **3 秒**讀一次清單 | 氣泡、紅色數字、提示音、搖晃、展開／縮小；額度警示也是它自己算的 |

所以：**有 hook 的事＝Windows 通知（即時）＋小工具（約 3～9 秒內）**；**只靠掃描的事＝只有小工具，沒有 Windows 通知**。

## 通知形式的名詞

- **Windows 通知**：右下角彈出、停在螢幕上直到你關掉（`toast.ps1`，帶 Windows 提醒音）；點它會開網頁清單（`pending.html`）。
- **小工具**：桌面上那個小圖示。有新的待決定時：冒出紅色氣泡「有待決定囉！· N 件」、圖上有紅色數字、搖一下、叮一聲（`Exclamation`）。
- **網頁清單**：`data\pending.html`，每 20 秒自己更新；只列「待決定」類，**不含額度警示**。

## 一、會通知的事

欄位「關掉」＝`config.json`（在安裝資料夾，見 README「設定」）。`notify` 預設全部是開的，只有寫 `false` 才會關；改完 hook／掃描立刻生效（下次執行就讀），**額度那個要重開小工具**。

| 什麼情況 | 誰偵測 | 通知形式 | 什麼時候消失（怎麼算已處理） | 可以關掉嗎 |
|---|---|---|---|---|
| **要你允許**：「是否允許 Claude 執行這個指令？」 | hook（`PermissionRequest`；`Notification` 的 `permission_prompt` 當備援，同一個對話 60 秒內重複的只算一次）。**只有 hook 看得到**，掃描不會發現它 | Windows 通知「Claude 需要你的允許（共 N 件）」＋小工具＋網頁清單；選填手機推播 | 掃描發現紀錄裡同一個工具＋同一個指令有結果了＝已處理；找不到對應紀錄超過 2 分鐘、或超過 1 天也當作處理了 | `notify.permission: false`（hook 直接不記錄，也不推手機） |
| **選項框**（`AskUserQuestion`） | hook（`PreToolUse`）＋掃描（紀錄裡有「問了」、沒有同一個 `tool_use_id` 的結果） | hook 有載入：Windows 通知「有選項框等你回答（共 N 件）」＋小工具；沒載入 hook：只有小工具 | 你回答（紀錄出現結果／hook 的 `PostToolUse`＝已回答）；被取消（`PostToolUseFailure`）＝已取消；對話檔 3 天沒動，也會被當作處理了 | `notify.question: false` |
| **收尾提問卡**（桌面版 `wrap_up`，有 `ask` 才算） | hook（`PreToolUse`，工具名要符合 `mcp__.*wrap_up`）＋掃描 | hook 有載入：Windows 通知「有問題等你決定（共 N 件）」＋小工具；沒載入：只有小工具 | 紀錄出現**你本人**的訊息（`origin.kind = human`），或 Claude 之後又呼叫了別的工具 | `notify.wrapup: false` |
| **建議任務卡片**（Claude 用 `start_session`、`own_initiative` 放出來等你按「開始」） | **只有掃描**（hook 沒有掛 `start_session`） | 只有小工具（標籤「等你按開始」）＋網頁清單；**沒有 Windows 通知、沒有手機推播** | 符合任一項就消失：桌面版對話檔記了這張卡已被開成新對話（`spawnedFrom.taskId`）或已處理（`resolvedBackgroundTaskSuggestions`）；放卡片的對話後來叫了 `dismiss_task` 或用 `proposal_id` 再叫一次；紀錄裡有 `The user started your proposal task_…`；別的對話第一句話含這張卡開頭 40 個字；你在小工具列上按右鍵「知道了」（7 天內不再顯示）；放超過 **7 天**；放卡片的那個對話檔 3 天沒動（掃描不再看它）也會消失 | `notify.proposal: false`；單張：右鍵「知道了」 |
| **Fable 提醒**（有對話最近 20 分鐘內是 Fable 模型在回） | 只有掃描 | 只有小工具（標籤「Fable 提醒」）＋網頁清單；沒有 Windows 通知 | 該對話超過 20 分鐘沒有 Fable 回覆；或桌面版記的「現在模型」已經不是 Fable；或你右鍵「知道了」（該對話 12 小時內不再提醒） | `notify.fable: false`；單一對話：右鍵「知道了」 |
| **額度警示**：用量 ≥90%（只做明確要的事）、≥98%（全面停止） | 只有小工具（讀 `data\usage.json`，來源是狀態列小模組、`usage-poll.mjs` 或右鍵「回報額度 %」手動填） | 只有小工具（標籤「額度 N%」，排在清單最前面）；**不在網頁清單、沒有 Windows 通知** | 用量掉到 90% 以下；`usage.json` 超過 12 小時沒更新；那個額度視窗已經重置（手動填的不看重置）；右鍵「回報額度 %」填 0 清掉 | `notify.usage: false`（要重開小工具）；不裝狀態列模組、也不登入終端機版，就根本沒有數字 |
| **手機推播**（選填，ntfy 或飛傳「待決定信箱」） | hook（跟上面三種 hook 通知同時發） | 手機通知，預設只寫「回電腦看待決定清單」；`approve` 開啟才能在手機按允許／拒絕。ntfy 不管你在不在電腦前都推；飛傳預設只在你離開電腦 60 秒以上才推 | 手機上自己處理；核准逾時＝電腦上照常跳原本的允許視窗 | 不設 `ntfy.topic`／`push` 就是關。**注意：`toast: false` 只關 Windows 通知，手機推播照送**；`notify.*: false` 兩個都關 |

### 新通知出現時，小工具的反應（規則）

| 動作 | 規則 | 可以關掉嗎 |
|---|---|---|
| 紅色數字 | 數字＝清單上所有「待決定」＋額度警示的總數；變多、變少都會更新 | 否 |
| 氣泡「有待決定囉！· N 件」 | N>0 就顯示；清單打開、或小工具已縮小時不顯示 | 設定視窗可改說的話；縮小見下 |
| 叮一聲＋搖一下＋展開 | **件數比上一次多**才觸發（小工具剛啟動時，清單裡本來就有的也會響一次）。電子雞睡著會被叫醒 | 設定視窗「有新的待決定時發出提示音」（只管聲音，搖晃關不掉） |
| 自動縮小、收起 | 沒人碰（滑鼠不在小工具上、清單沒開）超過 20 秒就慢慢縮小並收起氣泡；滑鼠移上去或有新通知就恢復 | 設定視窗「沒有新通知就自動縮小…」、右鍵「沒人碰幾秒後開始縮小…」 |
| 清單自動收起 | 預設 0＝不自動收，按「收起來」才收 | 設定視窗／右鍵可改秒數 |
| 滑鼠碰到就打開清單 | 預設關（點一下才開） | 設定視窗勾選 |
| 沒有待決定時把圖藏起來 | 預設不藏 | 設定視窗勾選 |

## 二、不會通知的事（小工具裡看得到，但不會響、不算進紅色數字）

| 情況 | 說明 |
|---|---|
| 「進行中」分頁：還在跑的對話、背景程式（下載、轉檔、腳本） | 只有分頁標題的數字與「先別關機」那一列，沒有氣泡、沒有聲音 |
| 「中斷」分頁：疑似斷線的對話（紀錄停在做事途中且安靜超過 5 分鐘） | 只有分頁標題的數字 |
| 「週 N%」小條 | 只變色（≥70% 黃、≥90% 紅），不通知；≥90% 才會另外出現上面的「額度警示」 |
| 已封存的桌面版對話 | 掃描遇到**新的**待決定時，若該對話已封存就略過 |
| 已經處理的、已取消的 | 只留在網頁清單的「最近回答過的」（最多 12 筆，3 天） |
| 其他 hook 事件 | `idle_prompt`、`elicitation_dialog` 之類的 `Notification`，hook 的 matcher 只接 `permission_prompt`，不處理 |

## 三、已知的誤報與漏報

| 類型 | 狀況 | 怎麼辦 |
|---|---|---|
| 誤報 | **建議任務卡片按 ✕ 關掉**：本機紀錄裡看不到這個動作，卡片會一直列到 7 天過期。桌面版的 `resolvedBackgroundTaskSuggestions` 有沒有記 ✕：**未驗證** | 在小工具列上按右鍵「知道了」 |
| 誤報 | 建議任務卡片被按了「開始」，但新對話的第一句話被改過、桌面版對話檔又沒有 `spawnedFrom.taskId`：判斷不出來 | 右鍵「知道了」 |
| 誤報 | 收尾提問卡：你用「按鈕」回答，紀錄裡算不算「你本人的訊息」：**未驗證**（程式只認 `origin.kind = human`） | 看到沒消失就回報；右鍵沒有「知道了」，等 Claude 再動手或你再說話就會消失 |
| 誤報 | 掃描只讀每個紀錄檔**最後 600KB**、且只看 3 天內有動過的檔：太舊的不會被追蹤 | — |
| 漏報 | 建議任務卡片**沒有 Windows 通知**（hook 沒掛 `start_session`），要看小工具；Fable 提醒、額度警示同理 | 要即時通知需要新增 hook（目前沒做） |
| 漏報 | hook 的 matcher 目前只涵蓋 `PreToolUse: AskUserQuestion｜mcp__.*wrap_up`、`PostToolUse／PostToolUseFailure: AskUserQuestion`、`PermissionRequest`、`Notification: permission_prompt`；其他需要你點的畫面（例如計畫確認 `ExitPlanMode`、`idle_prompt`）是否有被 `PermissionRequest` 接到：**未驗證** | — |
| 漏報 | 建議任務卡片**只認 `own_initiative`**；「請你選要不要另開對話」那種（`offer`，會等你回答）不會被抓到：**未驗證**那種卡片在紀錄裡長怎樣 | — |
| 漏報 | 對話是在 hook 註冊**之前**開的：沒有權限確認通知、沒有 Windows 通知（選項框、提問卡、卡片、Fable 仍由掃描補上，只有小工具） | 重開那個對話 |
| 漏報 | 叮一聲／搖晃只在「件數變多」時觸發：3 秒內剛好一件處理掉、另一件進來，件數沒變，不會響（氣泡與清單仍會更新） | — |
| 漏報 | 同一個對話 60 秒內有第二個**不同**的權限確認，而第一個還沒處理：只補工具資訊，不會再跳一次（平行工具呼叫才會發生）：**未驗證** | — |
| 漏報 | Windows「勿擾／專注輔助」開著時 Windows 通知會不會顯示：**未驗證**（小工具不受影響） | — |
| 說明 | 同一件事（有 hook 的三種）會**響兩次**：先 Windows 通知（即時），幾秒後小工具叮一聲。這是設計，不是重複偵測 | 設定視窗關提示音，或 `toast: false` |
