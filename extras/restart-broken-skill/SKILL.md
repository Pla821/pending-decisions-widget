# 重啟「中斷」的對話

小工具的「中斷」分頁＝對話最後一筆不是「回完了」、沒在等人回答、安靜超過 5 分鐘（可能斷線、當機、額度用完、被關掉）。小工具自己不能對對話說話，所以由這個 skill 代勞。

## 步驟（照順序，不要跳）

1. **用量守門**：先用 `get_usage`。任一額度窗 ≥90% → 不做，告訴使用者目前 %，停。（每個被叫醒的對話都要重讀整段對話，長對話很貴。）
2. **讀名單**：讀 `%USERPROFILE%\.claude\pending-decisions\data\recent.json` 的 `broken` 陣列（欄位：`title`、`local`＝桌面版對話 id、`cwd`、`stopped`＝停在哪、`said`＝它最後說的話、`at`）。檔案太舊（`at` 超過 10 分鐘前）就先請使用者等小工具重掃，或自己跑 `node "%USERPROFILE%\.claude\pending-decisions\bin\decision-scan.mjs"` 再讀。
3. **過濾**：用 `list_sessions` 對照 `local`——
   - 已封存（archived）的跳過；
   - `isRunning` 的跳過（它沒中斷，只是還在跑）；
   - `local` 是空的跳過；
   - 這個對話自己（正在執行這個 skill 的）跳過；
   - `stopped` 開頭是「你說：」且內容像系統訊息（`<system-reminder>`）的，標「可能誤報」，預設不叫。
4. **列表給使用者看**（四欄表格：項目｜狀態｜停在哪｜下一步），然後用 **AskUserQuestion** 問一次：「全部叫醒這 N 個？」選項：全部叫醒（推薦）／只叫最近 3 個／取消。不要只在文字裡問。
5. **叫醒**：對每個要叫的對話用 `send_message`（`to`＝它的 `local` id），訊息固定這一句，`停在哪` 換成它的 `stopped`：
   > 剛剛好像斷線或中斷了。請先看紀錄，確認你上一步做到哪（我這邊看到最後停在：<stopped>），已經做完的不要重做，沒做完的從那裡接著做，做完用一句話跟我說。
   - 一次最多送 3 個，其餘等前面的有回應再送；同時叫醒太多＝額度一下燒光。
   - 不要先把它們內容讀進這個對話（大輸出別進主對話）。
6. **回報**：用四欄表格列出：叫了哪些、跳過哪些（原因）、哪些送失敗。表後最多三行；不寫「待辦」，沒做完的用 AskUserQuestion 問。

## 不要做

- 不要替對話決定任何事、不要改它們的檔案、不要啟動新對話。
- 不要重複叫同一個對話（10 分鐘內叫過就跳過）。
- 小工具的名單可能含誤報（對話其實已經做完只是最後一筆是工具結果），所以第 4 步一定要讓使用者確認。
